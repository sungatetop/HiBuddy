# HiBuddy 需求文档（PRD）

> 状态：draft（待评审）。技术选型与实现架构见 [system-architecture.md](../architecture/system-architecture.md)，本文档不涉及实现技术。

## 1. 背景与目标

**问题**：通用对话助手只能"问答"，无法替用户完成跨多步的实际工作；用户把任务交给 Agent 后，过程是黑盒——看不到它要做什么、做错了无法拦、做完了说不清怎么做的。

**产品决策**：HiBuddy 是一个**个人工作伙伴（personal AI coworker）**。用户把一个目标托付给它，它规划步骤、调用工具、产出交付物；全过程对用户可见（要做什么、正在做什么、用了什么工具）、可控（随时打断、确认、纠偏）、可回溯（每一步留痕可回看）。

**预期可观察结果**：

- 用户发出一条目标后，无需逐步指挥，Agent 能自主推进到完成或主动停下来询问。
- 任务过程中的每个工具调用、每次状态变化都在界面上可见。
- 中间结果和最终结果不只是文字：图表、表单、面板等可交互界面直接出现在对话中，用户可以点击、修改、反喂给 Agent。
- 同一账号在桌面应用与浏览器中获得一致的功能与连续的会话体验。

## 2. 产品契约

| 要素 | 定义 |
|---|---|
| 主用户 | 单用户的个人知识工作者 / 开发者；产品本地优先，无多人协作角色 |
| 触发 | 用户在会话（Thread）中下达一条目标或问题 |
| 核心工作 | Agent 将目标展开为任务（Run）：规划步骤 → 调用工具 → 流式产出内容与界面 → 交付结果 |
| 完成条件 | 任务到达 completed：存在明确交付物（回答/文件/图表/可交互界面），且执行记录完整可回看 |
| 信任边界 | 高风险动作先确认；全部执行留痕；用户数据本地优先 [Assumption, TBD] |

## 3. 范围

### 3.1 P0 最小闭环

配置模型 → 创建会话 → 下达目标 → Agent 规划与工具执行（每步可见）→ 生成式界面呈现结果 → 用户介入（确认/打断/补充输入）→ 任务完成或失败恢复。桌面端与网页端功能一致。

### 3.2 P1（本期不做，架构预留）

- 多会话并行执行、后台任务队列
- 跨会话记忆、个性化技能包
- 外部工具生态（MCP 接入第三方工具）
- 定时/周期任务
- 数据云同步与多设备漫游

### 3.3 明确排除（P0）

- 托管计费与产品方代付模型费用（采用用户自带密钥模式）
- 团队/多人协作、权限管理
- 移动端

## 4. 对象模型与状态

### 4.1 核心对象

| 对象 | 说明 | 关键字段 |
|---|---|---|
| 会话 Thread | 用户与 Agent 的连续对话容器 | id、标题（首条消息自动生成，可改）、创建/更新时间、状态 |
| 任务 Run | 一次目标执行的实例，归属 Thread | id、目标输入、状态、起止时间、关联工具调用与产出 |
| 消息 Message | 用户 / Agent / 工具的对话条目 | id、角色、内容（文本/富文本/界面引用）、时间 |
| 工具调用 ToolCall | Agent 执行一次工具的记录 | id、工具名、参数摘要、风险等级、审批记录、结果摘要、状态 |
| 交付物 Artifact | 任务产出的持久结果 | id、类型（文件/图表/文档/界面）、存储位置、生成来源 Run |
| 画布 Canvas | Agent 产出的可交互界面实例 | id、版本、来源 Run、生命周期（随会话驻留）、用户交互记录 |

### 4.2 Run 状态机

```
created ──► running ──► completed
              │  ▲
              ▼  │（确认通过后继续）
        waiting_approval
              │
              ├──► cancelled（用户取消）
              └──► failed（错误且不可恢复）
```

| 状态 | 含义 | 允许的用户操作 |
|---|---|---|
| created | 已接收未开始 | 取消 |
| running | Agent 执行中 | 打断（转 cancelled）、查看进度 |
| waiting_approval | 等待用户确认高风险动作 | 批准一次 / 批准并本会话内免再询 / 拒绝（Agent 收到拒绝并调整方案） |
| completed | 有交付物、记录完整 | 回看、重开新任务 |
| failed | 执行失败 | 查看原因、重试（生成新 Run）、反馈 |
| cancelled | 用户终止 | 回看已执行部分、重试 |

### 4.3 Thread 状态

`active ⇄ archived`、`archived → deleted`。deleted 为软删除，保留 30 天后物理清除 [Assumption, TBD]。

## 5. 功能需求

### FR-01 会话管理

- **目的**：承载用户与 Agent 的全部交互历史。
- **触发**：用户新建会话、打开历史会话、归档/删除会话。
- **规则**：
  1. 新会话创建即进入输入就绪态；首条用户消息发出后自动生成标题。
  2. 会话列表按最近更新排序，展示标题、最后消息摘要、未完成任务标记。
  3. 归档会话不可继续对话，可恢复；删除需二次确认，删除后其下任务记录与交付物一并不可见。
- **状态变更**：Thread 状态按 4.3 迁移；列表实时反映。
- **异常**：历史加载失败允许重试；删除失败不改变本地状态并提示。

### FR-02 任务执行与生命周期

- **目的**：把一条目标变成一次可控的多步执行。
- **触发**：用户在 Thread 中发送目标消息（可附文件/图片 [Assumption, TBD]）。
- **处理规则**：
  1. 每个 Run 按序执行：同一 Thread 内同时只有一个活跃 Run（P0 串行；用户可在活跃 Run 存在时发消息，消息进入队列并在当前 Run 结束后处理，或选择打断当前 Run）。
  2. 执行过程中向用户实时呈现：当前步骤、正在调用的工具（名称+参数摘要）、流式文本输出、推理摘要（可折叠）。
  3. 子代理/子任务的出现与结束必须可见（名称、进度）。
  4. 用户可随时打断：打断后 Agent 收到终止通知，已完成部分保留，Run 转 cancelled。
  5. 运行时长超过阈值（默认 120 秒 [Assumption, TBD]）无任何事件输出时，界面给出"仍在运行/可能卡住"的提示并允许打断。
- **结果与状态变更**：按 4.2 状态机迁移；completed 时生成 Run 摘要（目标、结果、工具调用统计、耗时）。
- **异常**：模型请求失败自动重试 1 次；仍失败转 failed 并展示原因；用户可手动重试（生成新 Run，携带原上下文）。

### FR-03 工具执行与审批

- **目的**：让 Agent 具备真实操作能力，同时高风险动作处于用户控制之下。
- **触发**：Agent 在执行中决定调用工具。
- **工具分级与审批**（共享规则 SR-01，见 §6.1）：

| 等级 | 定义 | P0 内置工具 [Assumption, TBD] | 执行策略 |
|---|---|---|---|
| L0 只读 | 不改变任何用户数据与外部状态 | 网页读取、文件读取（工作区内） | 自动执行，留痕展示 |
| L1 写入 | 改变本地工作区数据 | 文件写入、文件整理 | 默认需确认；用户可选择"本会话内免再询" |
| L2 外部效应 | 影响工作区之外的世界 | P0 不内置；代码执行默认关闭，可在设置中开启（开启后按 L1 处理，且在隔离环境执行） | 每次确认，不可免询 |

- **处理规则**：
  1. 进入审批时 Run 转 waiting_approval，界面展示：工具名、参数全文、影响范围说明、批准/拒绝/免再询三选项。
  2. 拒绝不是报错：Agent 收到"用户拒绝了该操作"的反馈并继续调整方案；同一 Run 内连续 3 次被拒 [Assumption, TBD] 则 Agent 应停下询问用户意图。
  3. 每次工具调用在执行记录中留存：时间、参数全文、结果摘要、审批来源（自动/用户批准/免再询授权）。
- **异常**：工具执行超时/报错时 Agent 收到错误并可自行调整；连续失败终止 Run 并转 failed。

### FR-04 生成式界面呈现

- **目的**：Agent 的产出不止文字——直接在对话中呈现可交互界面，用户与界面交互的结果反喂给 Agent。
- **触发**：Agent 在回复中决定产出结构化界面（图表、表单、对比面板、计算器等）。
- **处理规则**：
  1. **流式渲染**：界面随生成过程逐步出现，不等完整生成。
  2. **两类形态**：①内嵌——出现在消息流中，适合单次图表/表单；②画布——在侧边面板打开并跨轮次驻留，适合持续使用的工具型界面。
  3. **交互回传**：界面上的用户操作（提交表单、点击选项、修改参数）作为结构化输入回传给 Agent，Agent 据此继续推理；交互同时记录在画布的交互历史中。
  4. **数据输入**：界面可消费任务上下文数据（如执行结果、文件内容摘要）。
  5. **安全呈现**：Agent 产出的界面在隔离容器中渲染，不能访问用户系统与密钥（边界规则 SR-02，见 §6.2）。
- **状态变更**：Canvas 创建后随会话驻留；用户可关闭/重开画布；画布版本随 Agent 更新递增，用户可回看历史版本。
- **异常**：界面渲染失败时降级为等效静态内容（图表转表格、界面转截图式占位）并提示。

### FR-05 共享状态与接管

- **目的**：用户与 Agent 就任务状态保持同一份事实，用户可随时"接手改一点再还回去"。
- **处理规则**：
  1. 每个 Run 维护一份共享任务状态（如待办清单、当前计划、关键参数），Agent 更实时用户可见。
  2. 用户可直接编辑共享状态中的开放字段（如勾选待办、修改参数）；Agent 在后续步骤读到用户修改并遵循。
  3. 状态变更双方可见来源标识（Agent 改的 / 用户改的）。
- **异常**：用户编辑与 Agent 更新冲突时，以时间戳新者为准并提示被覆盖方 [Assumption, TBD]。

### FR-06 模型配置（BYOK）

- **目的**：用户自带模型密钥，产品不托管计费。
- **触发**：首次使用引导、设置页修改。
- **规则**：
  1. 支持 Provider 列表：DeepSeek、OpenAI、Anthropic、OpenRouter 及自定义 OpenAI 兼容端点 [Assumption, TBD]。
  2. 字段：Provider、API Key（掩码显示、可清除）、可选 base URL、模型选择、温度等采样参数（默认值预置）。
  3. Key 保存后立即校验有效性（发起一次最小请求），失败给出具体原因（无效/额度/网络）。
  4. 密钥仅存于本机安全存储，不上传产品方服务器；界面与日志中永不明文出现（边界规则 SR-03，见 §6.3）。
  5. 支持多 Provider 配置并存，会话级切换；当前 Provider 失效时任务失败原因中明确指向配置问题。
- **异常**：未配置 Provider 时发起任务 → 阻断并引导到配置页。

### FR-07 双端一致

- **目的**：桌面应用与浏览器端提供一致体验。
- **规则**：
  1. 功能对等：FR-01～FR-06 全部能力在两端一致 [Assumption, TBD]。
  2. 桌面端独有：系统级通知（Run 需要审批或完成时，窗口失焦则发系统通知）、本地服务随桌面应用启停。
  3. 网页端依赖浏览器标签页存活；断线重连后会话与运行状态自动恢复（进行中的 Run 继续展示进度）。
  4. 窗口尺寸适配：桌面端最小窗口、网页端响应式至平板宽度 [Assumption, TBD]。

### FR-08 执行记录与审计

- **目的**：任何任务事后说得清"怎么做的"。
- **规则**：
  1. 每个 Run 生成时间线：步骤、工具调用（含参数与结果摘要）、审批事件、状态变更、产出。
  2. 时间线在 Run 结束后只读可回看；进行中实时追加。
  3. 支持导出单次 Run 记录为文件（Markdown）[Assumption, TBD]。
- **异常**：记录写入失败不阻断任务执行，界面标记"部分记录缺失"。

### FR-09 异常与恢复

| 场景 | 行为 |
|---|---|
| 网络中断 | 客户端自动重连；进行中 Run 的进度恢复展示；模型请求中断则按 FR-02 重试 |
| 密钥失效/额度不足 | Run 转 failed，原因明确指向配置，一键跳转设置页 |
| 应用/页面意外关闭 | 桌面端本地服务继续完成当前 Run（完成后可通知）；网页端 Run 转入后台，重开页面恢复状态 |
| 版本升级 | 桌面端升级不丢失会话与配置；进行中 Run 先完成或安全终止再升级 [Assumption, TBD] |

## 6. 共享规则

### 6.1 SR-01 工具风险分级与审批

- 分级定义与各级行为以 FR-03 表格为唯一权威。
- "免再询"授权范围 = 当前会话 × 当前工具 × 当前风险等级；新会话、工具升级风险等级、产品升级后授权失效。
- 所有审批事件进入 FR-08 时间线。

### 6.2 SR-02 生成式界面安全边界

- Agent 产出的界面运行在隔离容器内：无网络请求白名单以外的访问、无本地文件访问、无密钥读取。
- 界面代码与数据仅来自当前任务的上下文。
- 边界内允许：消费会话数据、向 Agent 回传交互、使用内置展示组件。

### 6.3 SR-03 密钥与数据边界

- API Key 仅存本机安全存储，仅供模型请求使用。
- 会话数据本地优先 [Assumption, TBD]：不主动上传产品方服务器；用户显式导出除外。
- 日志脱敏：密钥、完整工具参数（可含敏感内容）不在普通日志输出。
